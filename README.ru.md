# UnityMvpFramework

[English](README.md)

UI-фреймворк для Unity на основе MVP, VContainer, R3 и UniTask. Презентеры управляют поведением окон, а View загружаются и освобождаются через Addressables.

## Требования

Unity **6000.3.16f1**, Git и **.NET 8 Runtime** для восстановления зависимостей.

Зависимости ядра: VContainer **1.18.0**, UniTask **2.5.11**, R3 / R3.Unity **1.3.1**, Addressables **2.9.1**. Точные версии закреплены в `Packages/manifest.json`, `Packages/packages-lock.json` и `Assets/packages.config`.

## Подключение

1. Клонируйте репозиторий.
2. До открытия Unity восстановите NuGet-зависимости из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File Tools/RestoreDependencies.ps1
```

Для переносимой установки .NET передайте `-DotnetPath "путь/к/dotnet.exe"`. При первом восстановлении нужен интернет.

3. Откройте проект в указанной версии Unity и дождитесь импорта.

Репозиторий содержит ядро и тесты. Сцен приложения и сборки игрока нет.

Для переноса в свой проект скопируйте `Assets/MVPFramework` вместе с `.meta` и установите зависимости ядра, включая NuGet-зависимости R3.

## Контракт интеграции

- Наследуйте View от `BaseView`, презентер — от `BasePresenter<TView>`. Каждый конкретный презентер помечайте `UIWindowAttribute`.
- Компонент View должен находиться на корне префаба. Имя типа View и адрес Addressables должны совпадать; имена View должны быть уникальными.
- Зарегистрируйте через VContainer `ViewLoader` как `IViewLoader`, `UINavigator` как его интерфейсы навигации и провайдер `ICameraProvider`. Навигатор и загрузчик должны принадлежать одному scope.
- Зарегистрируйте настроенный компонент `UIRootProvider`: назначьте контейнер каждого используемого `UILayer` и неактивный временный контейнер. Подавление камеры включайте при наличии корректного провайдера камеры.
- Регистрируйте презентеры с временем жизни Scoped через `AsWindow()`. Вызывайте `RegisterWindows()` один раз на scope.
- Открывайте начальные окна после инициализации из entry point VContainer. API навигации вызывайте в главном потоке Unity.

## Жизненный цикл

| API / контракт | Поведение |
| --- | --- |
| `ShowAsync<T>()` | Открывает окно; одновременные вызовы без payload используют общую операцию открытия. |
| `ShowAsync<T, TPayload>()` | Передаёт данные через `IPayloadReceiver<TPayload>`. Перед новым payload закройте окно. |
| `PreloadAsync<T>()` | Загружает неактивную View без открытия окна. |
| `Hide<T>()` | Закрывает и освобождает открытую или предзагруженную View, отменяет открытие. |
| `BeforeShow` | Получает токен отмены и `CompositeDisposable` для подписок View. |
| Освобождение scope | Отменяет навигацию и освобождает экземпляры Addressables, принадлежащие загрузчику. |

При закрытии навигатор освобождает подписки View. Отмена внешнего ожидания через `AttachExternalCancellation` отменяет только ожидание вызывающей стороны; общая операция отменяется закрытием окна или освобождением scope.

Слои: `Background`, `HUD`, `Window`, `Popup`, `Topmost`. Полноэкранные окна могут обнулять и восстанавливать маску камеры сцены. Владение вводом и прикладные правила модальности реализуются в приложении.

## Тесты

Запустите EditMode и PlayMode через **Window → General → Test Runner**.

- `Assets/Tests/EditMode`: регистрация, payload, повторная навигация, восстановление камеры, отмена и освобождение подписок.
- `Assets/Tests/PlayMode`: настоящая загрузка Addressables, отмена, освобождение экземпляров, повторная загрузка и восстановление после отсутствующего адреса.

Два пустых префаба в `Assets/Tests/PlayMode/Fixtures` и настройки Addressables нужны только интеграционным тестам. Для Addressables Play Mode Script выберите **Use Asset Database (fastest)**.
